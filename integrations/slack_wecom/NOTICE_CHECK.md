# 回读已有通知的校验回执

`ai-brief-notice-check` 随独立转发器 wheel 安装，把现有 Slack 认证读取器
接到离线投递计划使用的同一个 `check_received_notice` 函数。
它不打开转发账本、不推进游标、不向 Slack 或企微发送消息、不预留 outbox
尝试，也不授权再次上传；没有新增服务或监听端口。

由现有转发器账号运行，指定该账号的私有配置目录，沿用配置与凭据的所有权检查。
仅使用已有 Slack 用户令牌的 `im:history` 和 `files:read` 权限，凭据留在宿主机。
输入不能覆盖配置中的连接器身份或目标私信。命令不创建凭据或修改配置。

```sh
ai-brief-notice-check --root /path/to/relay-root < expected-notice.json
```

输入是有大小上限的 UTF-8 JSON，且只含三个字段：

- `message_ts`：最终私信中原始消息的精确时间戳。
- `file_id`：原先预留的海报文件 ID，不得替换成补传文件。
- `notice_manifest`：由准备好的报告生成的完整预期清单，含全部子标题、URL、
  正文、报告摘要和原始海报摘要。不能从待校验消息反向拼造清单。

命令先认证读取身份，再按精确时间戳获取完整原始消息，检查消息、App 与附件身份，
下载实际文件字节。发布清单只能从配置中的报告站读取，其全部内容字段必须匹配预期。
后续整站部署允许使用不同提交，但报告、正文和图片摘要必须保持一致。
图片下载后再次读取消息和发布清单，拒绝校验期间发生的变化。网络失败、分页、
歧义、文件改变或结果未知都会阻止成功回执；没有隐藏的写入重试。

成功时 stdout 返回 `slack_status: verified` 以及已有回执字段：频道、消息时间戳、
文件 ID、实际字节数和 SHA256。`wecom_status` 始终为 `not_checked`，
`publication_status` 仍为 `not_checked`：此命令不能代替 Publisher 的完整网页与
来源校验，也不能代替转发器的真实企微送达回执。观测到的整站部署提交单独返回。
不返回原始消息、图片字节、下载地址、令牌或 Webhook。失败时非零退出，输出固定的
`not_verified` 结果，不包含底层传输错误文本。

## 尚未接入的发送部分

发送仍使用云端连接器的上传票据和上传完成工具。Publisher 机器人与转发器读取账号
都是不同身份，不能代替云端连接器发送。定时驱动仍须建立受认证的调用路径，将本命令
的回执交给现有持久发送日志与 outbox；本命令不安装驱动，也不修改定时任务。

原生上传路径仍需在私有控制频道实测：PNG 原字节必须在上传及预期的未分享等待时间后
保持一致。历史原生上传曾改写 PNG 元数据，像素相同不能替代原字节契约。
校验失败后只能核对同一文件，不得自动换 ID 补传。outbox 启用和零入选通知契约
也属于后续接入工作。离线测试通过不代表无人值守投递已经可用。
