# 原始海报的报告包传输

通过身份验证的分篇通知可以携带且仅携带一个名为 `ai-brief-bundle.json`
的托管 JSON 文件，复用既有报告包格式。此传输模式必须明确指定，不能作为
PNG 哈希失败后的降级方式。原有发送者、App、工作区、目的地、可见消息块和归属校验继续生效。

发送任何文字或图片前，转发器从固定公开来源读取发布清单，核对规范路径、声明文件、
严格 base64 编码、文件哈希、期次、报告元数据的精确哈希，以及由元数据重建的通知清单。
取出的原始海报保持逐字节不变，不重新编码或删除任何块。C2PA 数据参与完整字节哈希；
这不代表已经验证 C2PA 签名的密码学真实性。

独立校验器的既有消息、文件和清单请求新增 `transport:report_bundle_v1`、
`bundle_sha256` 和 `bundle_bytes`。预期值来自 Publisher 已保存的不可变报告包。
校验器读取实际最终文件，分别证明整包和原始海报的哈希及大小，再次检查消息与发布状态。
回执的 `transport_*` 字段始终描述实际 JSON 文件字节；`poster_sha256`、`poster_bytes`
描述原图。旧 PNG 请求保持兼容。

企微仍接收各子标题及 URL 正文和一张原始图片，不接收 JSON 附件。账本结构、游标、
期次去重规则不变。网络读取不完整时保留原消息重读；无效数据在发送文字前失败关闭；
结果不确定的写入仍禁止重试。

发送器使用本模式前，先一并部署兼容的转发器 wheel 和独立校验器。固定控制入口及安全权限不变。
离线测试拦截所有投递；它不证明真实最终私信的传输保留期，也不启用发送器、修改定时任务或发送企微。
